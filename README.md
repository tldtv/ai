# Агент сигналов для точек роста Авито.Работы

Репозиторий с пайплайном, который по расписанию собирает сигналы из
источников (RSS), размечает их по рынку, отделяет факт от интерпретации
через Claude, формулирует гипотезу возможности с оценкой по рубрике —
и обновляет бэклог и дашборд со светофором.

## Структура

```
config/parameters.yaml      — все управляемые параметры (пороги, веса,
                               источники, целевое окно дат)
data/backlog.csv            — бэклог идей (открывается и в Excel/Sheets)
src/fetch_sources.py        — механический слой: RSS + фильтр + теги + дедуп
src/analyze_signals.py      — смысловой слой: вызов Claude API
src/run_pipeline.py         — точка входа, запускает оба шага по очереди
src/build_dashboard.py      — собирает docs/index.html из backlog.csv
.github/workflows/
  weekly_signal_scan.yml    — расписание (по понедельникам) + ручной запуск
docs/index.html             — дашборд (генерируется, вручную не редактировать)
```

## Установка (один раз)

1. Создайте новый репозиторий на GitHub и загрузите в него все файлы
   этой папки (можно перетащить их в веб-интерфейс GitHub — drag & drop
   работает и для вложенных папок).
2. **Settings → Secrets and variables → Actions → New repository secret**
   — имя `ANTHROPIC_API_KEY`, значение — ключ с console.anthropic.com
   (раздел API Keys → Create Key). Там же привязывается карта — оплата
   идёт по факту использования, при таком объёме сигналов расход
   исчисляется центами в неделю.
3. **Settings → Pages** → Source: *Deploy from a branch* → ветка `main`,
   папка `/docs` → Save. Через минуту-две дашборд будет доступен по
   адресу вида `https://<ваш-логин>.github.io/<название-репозитория>/`.
4. Вкладка **Actions** — если GitHub спросит разрешение на запуск
   workflow, подтвердите.

## Как запускать

- **Автоматически** — каждый понедельник в 06:00 UTC (09:00 МСК), без
  вашего участия.
- **Вручную** — вкладка Actions → Weekly Signal Scan → Run workflow.
  Можно указать `mode=backfill` и даты, чтобы разово пройтись по
  источникам за прошлый период (см. ограничение ниже).

## Важное ограничение backfill

RSS-ленты обычно хранят только последние ~20–50 записей, а не архив за
несколько месяцев назад. Поэтому полностью автоматический backfill за
июнь–август 2026 может не дотянуться до части источников — их лента к
моменту запуска уже "прокрутилась" дальше. Практичный путь: разово
собрать этот период вручную (например, обычным поиском — так же, как
мы делали при тестировании подхода) и вписать найденные строки прямо в
`data/backlog.csv` по существующей схеме колонок. Дальше пайплайн будет
только дополнять этот файл, не перезаписывая его.

## Источники без RSS (Telegram-каналы, сайты без фида)

Пайплайн в этом виде читает только RSS. Источники без своего фида —
Telegram-каналы, сайты без `/feed` — этим кодом автоматически не
читаются. Варианты на следующую итерацию: сервис вроде rss.app,
который генерирует RSS из Telegram-канала или страницы без своего фида,
либо Telegram Bot API, если вы администратор нужных каналов. До тех пор
такие источники проверяются вручную и заносятся в `backlog.csv` так же,
как и результаты backfill.

## Настройка параметров

Всё, что можно менять без прикосновения к коду, находится в
`config/parameters.yaml`: пороги светофора, веса критериев
приоритизации, список источников, целевое окно дат, модель для анализа.
Отредактируйте файл (в веб-интерфейсе GitHub или в VS Code), закоммитьте
— при следующем запуске пайплайн уже использует новые значения. История
изменений параметров — это обычная история коммитов этого файла
(`git log -- config/parameters.yaml`), отдельный журнал вести не нужно.

## Осознанные упрощения этой версии (на что обратить внимание дальше)

- `cluster_id` не заполняется автоматически — кластеризация
  повторяющихся сигналов из разных источников оставлена на следующую
  итерацию (сейчас дедуп — только по точному совпадению ссылки).
- Источники ограничены RSS (см. пункт выше).
- Дашборд статический: обновляется при каждом запуске workflow, а не в
  реальном времени при каждом открытии страницы.
- Имя модели в `config/parameters.yaml -> llm.model` стоит проверить в
  консоли Anthropic перед первым запуском — актуальные названия моделей
  могут отличаться от того, что указано по умолчанию.

## Локальный запуск (необязательно)

```
pip install -r requirements.txt
cp .env.example .env   # и впишите туда свой ключ
export $(cat .env | xargs)
python src/run_pipeline.py --mode weekly
python src/build_dashboard.py
```
